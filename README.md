# varamon

Receive-only monitor for VARA HF signals.

varamon listens to receiver audio, finds each VARA HF transmission, works out its bandwidth mode and speed level, decodes the frame and checks its CRC. It reads recordings or a live audio input. It does not transmit.

## What it decodes

| Bandwidth mode | Levels | Signal |
|---|---|---|
| 2300 Hz | 1-4 | tone-keyed, 23 to 94 symbols/s |
| 2300 Hz | 5-9 | 3 to 10 carriers, 4-phase, 94 symbols/s |
| 2300 Hz | 10-16 | OFDM, 49 carriers, 4-phase to 32QAM |
| 500 Hz | 1-3 | tone-keyed |
| 2750 Hz | 1-4 | tone-keyed |

Not decoded: the higher levels of the 500 and 2750 Hz modes, control and handshake bursts, VARA FM, VARA SAT.

## Requirements

- Python 3.11 or newer
- numpy
- macOS, Linux or Windows
- For live use: a browser, and the receiver's audio on a sound input

## Install

```
git clone https://github.com/adswill/varamon
cd varamon
pip install .
```

or run it from the folder without installing: `pip install numpy`, then `python -m varamon`.

## Use

| Command | What it does |
|---|---|
| `python -m varamon` | opens the web page: open a recording or pick an audio input |
| `python -m varamon recording.wav` | decodes a recording and prints one line per transmission |
| `python -m varamon --hex recording.wav` | also prints the bytes of each decoded frame |
| `python -m varamon --selftest` | decodes generated test signals |
| `python -m varamon --help` | all options |

Recordings are 16-bit WAV of the receiver's audio in USB, at any sample rate. The first run prepares its tables, which takes about a minute; they are cached in `~/.varamon`. On Windows use `py` instead of `python`.

## Output

```
recording.wav: 31.4 s
   0.10 s   4.93 s  fsk  2300 Hz level  2    25 bytes  CRC OK     control 15 (reply 0, compressed 0, last 0, full 1)  score 0.98
   6.77 s   5.34 s  fsk  2300 Hz level  1    12 bytes  CRC OK     control 55 (reply 1, compressed 0, last 0, full 1)  score 0.98
5 transmissions, 5 decoded with correct CRC
```

Columns: start time, length, signal type, bandwidth mode, level, frame size, CRC result, the frame's control byte, and how well the level's pilot or marker pattern matched (0 to 1).

The web page shows the same list with a details pane, the frame bytes, a waterfall and level reading for live input, and CSV export.

## How it works

1. Transmissions are found by energy in the audio passband; short fades are bridged.
2. Each one is classed as tone-keyed, multi-carrier phase-keyed or OFDM.
3. The level is identified by its known pilot or marker pattern, which also gives timing and tuning offset.
4. Soft bits go through de-interleaving and a turbo decoder; the frame is accepted only if its CRC-16 is correct.

## Status

| Part | Verified against |
|---|---|
| 2300 Hz levels 1-2 | a real off-air recording |
| 2300 Hz levels 3-16, 500 Hz levels 1-3, 2750 Hz levels 1-4 | signals generated by this program only |
| Live input | recorded audio fed through the page's server |

Frame contents are shown as bytes; compression and higher-layer protocols are not interpreted.

## Testing

`python -m varamon --selftest` generates frames at several levels and bandwidth modes with noise and a tuning offset, scans them and compares. The same test runs on Linux and Windows through GitHub Actions.
